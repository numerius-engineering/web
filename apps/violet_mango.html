Violet Mango — How the Solver Works

A 2.5D Finite-Difference Time-Domain (FDTD) electromagnetic solver, running entirely client-side.

1. Overview

Violet Mango simulates electromagnetic current sources on a single 2D computational grid (the "grid plane") that sits at a chosen height in 3D space. Rather than restricting the physics to a single polarization, the solver tracks all six Cartesian field components (Ex, Ey, Ez, Hx, Hy, Hz) by assuming the geometry and fields are invariant along the axis perpendicular to the grid plane — the same assumption used for 2D waveguide cross-sections and cylindrical antenna problems. This is what "2.5D" refers to: a 2D grid producing a fully 3D field vector at every point.

2. Mode Decoupling (TMz / TEz)

Because the fields don't vary along z (∂/∂z = 0), Maxwell's curl equations split cleanly into two independent sets:

// TMz mode — driven by out-of-plane current Jz fields: Ez, Hx, Hy // TEz mode — driven by in-plane current Jx, Jy fields: Hz, Ex, Ey

These two modes do not exchange energy for isotropic materials, so the solver advances them simultaneously but independently on the same Yee grid. A source's orientation vector determines which mode(s) it excites: a purely out-of-plane dipole (dz only) drives TMz exclusively, a purely in-plane dipole (dx, dy) drives TEz exclusively, and a tilted dipole drives both — which is also why the out-of-plane Poynting component Sz is only non-zero when both modes are simultaneously excited (it comes from the cross-product of one mode's E-field with the other mode's H-field).

3. Update Equations

The grid uses the standard Yee leapfrog scheme: H-fields are updated a half timestep ahead of E-fields, cell sizes are uniform (Δx = Δy = dx), and materials are approximated with the collocated-grid convention (one εr/μr/σ value per cell, applied to every field component stored at that cell). With C0 the speed of light, ε0 and μ0 the vacuum permittivity/permeability, and dt the timestep:

// Magnetic field updates (TMz) Hx[i,j] -= (dt / (μ0·μr·dy)) · (Ez[i,j+1] - Ez[i,j]) Hy[i,j] += (dt / (μ0·μr·dx)) · (Ez[i+1,j] - Ez[i,j]) // Magnetic field update (TEz) Hz[i,j] -= (dt/μ0·μr) · [ (Ey[i+1,j]-Ey[i,j])/dx - (Ex[i,j+1]-Ex[i,j])/dy ] // Electric field update (TMz), with conductive loss + PEC clamp Ez[i,j] = Ca·Ez[i,j] + Cb·[ (Hy[i,j]-Hy[i-1,j])/dx - (Hx[i,j]-Hx[i,j-1])/dy - Jz[i,j] ] // Electric field updates (TEz) Ex[i,j] = Ca·Ex[i,j] + Cb·[ (Hz[i,j]-Hz[i,j-1])/dy - Jx[i,j] ] Ey[i,j] = Ca·Ey[i,j] + Cb·[ -(Hz[i,j]-Hz[i-1,j])/dx - Jy[i,j] ] // Loss coefficients, from conductivity σ and permittivity ε = ε0·εr Ca = (1 - σ·dt / 2ε) / (1 + σ·dt / 2ε) Cb = (dt/ε) / (1 + σ·dt / 2ε)

Cells flagged as a Perfect Electric Conductor (PEC) have every E-field component clamped to zero after each update, which is the standard "staircased PEC" approximation used throughout FDTD.

Time step & stability

The timestep is chosen from the 2D Courant–Friedrichs–Lewy (CFL) stability limit, scaled by the user-configurable CFL factor (default 0.98, must be < 1 for stability):

dt = CFL_factor · dx / (c · √2)

Absorbing boundary (PML)

The domain edges use a graded-conductivity absorbing layer: a polynomial-profile loss term σ(depth) is added to the update coefficients within the PML region (matched between electric and magnetic loss so the layer is approximately impedance-matched to free space), ramping from 0 at the PML's inner edge to a maximum value at the outer domain boundary. This is a simplified, single-field approximation of a full Convolutional PML — effective at absorbing outgoing waves with modest reflection, though not as reflection-free as a split-field CPML implementation.

4. Excitation & Steady State

All sources are single-frequency, continuous-wave (CW) sinusoids. The solver time-steps cycle by cycle, tracking the total electromagnetic energy across the entire domain (cycle-averaged, to cancel out the drive frequency's own oscillation) rather than a single probe point — a single point can sit near a field null and either look falsely settled or stay noisy indefinitely even once the overall solution has genuinely reached steady state. Convergence only triggers once that domain-energy metric has stayed within the convergence threshold across a full window of consecutive cycles (default 5, configurable), not just one favorable step — this avoids the false stops (and the never-quite-settling noise) that a single-point, single-step comparison is prone to. Otherwise it runs until the configured maximum number of cycles. Once stopped, it runs one additional full period, during which it:

  • Records field snapshots (for the time-history playback / animation), and
  • Accumulates a running discrete Fourier transform (DFT) at the excitation frequency, to extract the steady-state complex phasor fields (Ex, Ey, Ez, Hx, Hy, Hz) used for all "steady-state phasor" visualizations and the far-field transform.

5. Near-to-Far-Field Transform

The far-field radiation pattern is computed from the phasor fields using the equivalence principle on a rectangular Huygens surface placed just inside the PML. Equivalent electric and magnetic surface currents are derived from the tangential fields on that contour:

Js = n̂ × H (equivalent electric surface current) Ms = -n̂ × E (equivalent magnetic surface current)

These currents are integrated around the contour with the appropriate far-field phase factor exp(jk·r̂·r′) for each observation angle φ, separately for the TMz pattern (from Ez, Hx, Hy) and the TEz pattern (from Hz, Ex, Ey), producing the polar radiation pattern shown in the Visualize tab.

Approximate Directivity

Directivity is estimated by treating the far-field magnitude squared as proportional to radiation intensity, U(φ) ∝ pattern(φ)², and normalizing by the total power integrated around the full circle — the 2D/cylindrical analogue of the standard 4π-steradian directivity formula (using 2π radians in place of 4π steradians, consistent with this solver's z-invariant geometry):

D(φ) = 2π · U(φ) / ∫ U(φ) dφ

It's labeled "approximate" because it isn't impedance-calibrated to an absolute radiated-power reference — it's a relative measure derived purely from the shape of the computed pattern.

6. Materials

Material regions are rasterized onto the grid from geometric primitives, split into two families:

Surface primitives (open curves, w/ thickness)Closed-region primitives (filled area)
Line, Circular Arc, Elliptical Arc, Parabolic Arc, Spline, ƒ(x)Triangle, Circle, Ellipse, Dielectric Lens, Polygon (import only)

Each material carries relative permittivity εr, relative permeability μr, conductivity σ, and an optional PEC flag (which overrides εr/μr/σ with a perfect-conductor boundary condition). The elliptical arc uses the ellipse's native parametric angle convention; the parabolic arc is defined by vertex, focus, and aperture height, matching standard reflector-antenna convention.

Dielectric Lens

Placed via a guided wizard (button in the Closed Region toolbar) rather than click-drawn directly. A lens is defined by two independent surfaces — each flat, convex, or concave, with its own radius of curvature — plus an aperture span, center thickness, and rotation. The wizard offers six canonical types (Biconvex, Biconcave, Plano-Convex, Plano-Concave, Meniscus Converging/Diverging) and can derive the required radius (or radii) from a target focal length using the thin-lens form of the Lensmaker's equation:

1/f = (n - 1) · (1/R1 - 1/R2)

After placement, every parameter — including the surface types and radii — remains editable in the Materials panel, with a live focal-length readout, just like any other region.

CAD Import (SVG, DXF, Gerber)

The "Import CAD…" button (Materials tab) reads SVG, DXF, or Gerber (RS-274X) files directly — no external libraries, parsed from each format's own specification. After loading, a wizard lists every distinct layer found (DXF: group code 8; SVG: nearest containing <g> element; Gerber: one layer per file, since Gerber's convention is one file per copper/silkscreen/etc. layer) and lets you assign each one εr/μr/σ, a PEC flag, or skip it — plus a single editable import scale (auto-suggested from the file's own units where available: DXF's $INSUNITS, SVG's viewBox/width, Gerber's %MO%) and a Y-flip option (on by default for SVG, whose coordinate system is Y-down, unlike this app's Y-up world).

Supported entities: lines, circles, arcs, ellipses/elliptical arcs, closed and open polylines (including DXF's bulge-arc segments), SVG paths (cubic/quadratic beziers and elliptical arcs, flattened to polylines), and Gerber draws/flashes/regions with circular and rectangular apertures. Closed shapes import as a general filled Polygon material (arbitrary vertex count, ray-casting rasterization) unless they match a more specific primitive (circle, ellipse).

v1 limitations: DXF SPLINE entities without explicit fit points are approximated as straight-segment polylines rather than fully evaluated as NURBS; DXF HATCH supports simple polyline-boundary fills only; Gerber polygon/macro apertures are approximated as circles; and Gerber clear-polarity (subtractive) regions are imported as ordinary filled regions rather than true boolean cutouts. Review layers using these features before relying on the imported geometry.

7. Sources

Sources are defined in full 3D and projected onto the grid plane (a warning is shown if a source sits far from the plane's Z height). Five types are supported: point dipoles (with a 3D orientation vector), wire segments, loops, lumped ports, and rectangular apertures — wire/loop support a spatial current taper (uniform or sinusoidal) along their length.

The last two are field sources, not simple impressed currents, and are handled differently in the update equations:

Lumped Port

Modeled as the Norton equivalent of a voltage source V0 in series with an impedance R: an impressed current I0 = V0/R, plus a shunt conductance 1/R added to the local cell's loss coefficients. That shunt term is what makes it a real terminal impedance rather than a plain current source — a low-impedance port behaves like a near-short (heavily damping local field buildup even though it draws more current), while a high-impedance port allows more field buildup, mirroring real Thevenin/Norton port behavior. The equivalent conductivity is:

σport = 1 / (R · Δx)

added on top of whatever material/PML loss the cell already has, at each of the port's feed points.

Rectangular Aperture

An impressed-field source: rather than adding a current term, the chosen field component (set by its 3D orientation vector, same convention as the dipole) is hard-set directly at each sample point across the aperture, every timestep — overwriting whatever the normal FDTD update computed there, following one of three spatial distributions across the aperture's span:

  • Uniform — constant amplitude across the full span.
  • Sinusoidal — sin(π·u) for u∈[0,1], zero at both edges, matching the dominant-mode profile of a rectangular waveguide aperture.
  • Gaussian — exp(−t²/2σ²), t the centered position ∈[−0.5,0.5], with σ configurable as a fraction of the aperture span (a typical quasi-optical beam-launch profile).

8. Visualization

Any of the six complex phasor components can be viewed through a selectable function: Re, Im, Arg (rad/deg), Abs, or Abs². Derived real-valued quantities — |E|, |H|, and the Poynting vector components Sx, Sy, Sz, |S| — are also available. Color scales support linear, log, and dB modes with auto-ranging (dB auto-range fixes the floor 60 dB below the computed peak) or fully manual min/max.

Coordinate System (post-processing)

Fields are always solved in Cartesian coordinates, but since the 2.5D formulation already gives a full 3D vector (Ex,Ey,Ez / Hx,Hy,Hz) at every grid point, they can be re-projected for viewing into cylindrical (ρ,φ,z) or spherical (r,θ,φ) bases without re-running the solver — a pure post-processing step, selected via the Coordinate System control in the Visualize tab. Both are referenced from the world origin (x=y=0), and the spherical polar angle additionally uses the grid plane's Z height:

φ = atan2(y, x) θ = atan2(√(x²+y²), z_plane) Eρ = Ex·cosφ + Ey·sinφ E_r = Ex·sinθcosφ + Ey·sinθsinφ + Ez·cosθ Eφ = -Ex·sinφ + Ey·cosφ E_θ = Ex·cosθcosφ + Ey·cosθsinφ - Ez·sinθ Ez unchanged E_φ = same formula as cylindrical Eφ

For phasor views the rotation is applied to the real and imaginary parts separately (the coefficients above are real, so this is exactly equivalent to rotating the complex phasor), then the selected function (Re/Im/Arg/Abs/Abs²) is applied to the rotated result. The Poynting vector is rotated the same way, since it's already a real 3-vector at each point. |E|, |H|, and |S| are rotation-invariant and read identically in any coordinate system.

9. Data Export

Two independent JSON exports are available: a results export (steady-state phasor fields, far-field pattern and approximate directivity, and grid metadata) for downstream processing in Python/MATLAB/etc., and a project export (complete geometry, sources, and solver settings) for saving and reloading your setup. Exported phasor fields are always Cartesian — the coordinate-system control only affects the in-app view.
